# v1.0.0-beta3

## 日本語

- サーバークラッシュと起動失敗の通知を追加しました。致命的なサーバーログ、新しく生成されたサーバー用クラッシュレポートを検知します。検知は既定で有効です。
- Fabric・Forge・NeoForgeの新旧の代表的なログ形式に対応し、`Failed to start the server` / `Failed to start the minecraft server` や、Forge・NeoForgeのサーバー用MOD読み込み失敗を認識します。Minecraft本体の起動完了前に失敗した場合でも、次のローダー起動で再検知できます。
- 同じ障害の複数のログをまとめて通知し、クラッシュ直後の停止ログで正常終了の通知を重ねません。通常のMODエラー、チャット、クライアント用レポートや補助サービスの失敗による誤検知を抑えています。
- クラッシュレポートをmclo.gsへ共有する機能を追加しました。レポートが得られない場合は直近ログの末尾を使用します。アップロード前にWebhook URL、一般的な認証情報、IPアドレス、ホームディレクトリのユーザー名を可能な範囲で伏せます。自動アップロードは既定で無効です。
- 異常終了のお知らせとレポートリンクの送信先を、通常チャンネル・管理者チャンネル・両方から別々に設定できます。送信やアップロードに失敗しても通常の監視を継続します。
- 任意の `SERVER_PID` 監視を追加しました。ログやレポートを残さないJavaプロセスの終了も検知できます。プロセスを作り直した場合はPIDの更新と通知プログラムの再起動が必要です。
- リリースタグを付ける前に、対象コミットのWindows・Linuxビルドと単体実行ファイルの起動確認を行う公開手順を整備しました。

Windows x64 / Linux x64の実行ファイル、ZIP、SHA-256チェックサムを配布します。設定を保管して更新し、`--check-config` で確認してから通知プログラムを再起動してください。通知プログラムはMinecraftサーバーを起動する前から動かしてください。監視開始前からあるログやレポートは通知し直しません。

既存のTOML設定はそのまま利用でき、新しい設定を省略した場合は既定値を使います。アップロードを有効にする場合は `CRASH_REPORT_UPLOAD_ENABLED = true` を設定してください。送信先などの設定例はREADMEと `send-minecraft-notifications.example.toml` にあります。任意のMOD出力に含まれるすべての非公開情報を自動で判別できるわけではありません。

## English

- Added server crash and startup-failure alerts, enabled by default, based on definitive server log records and newly generated server crash reports.
- Recognize representative older and newer Fabric, Forge and NeoForge log formats, including `Failed to start the server`, `Failed to start the minecraft server`, and Forge/NeoForge server mod-loading failures. Another loader boot allows a new failure to be reported even when the previous attempt failed before Minecraft server readiness.
- Coalesce multiple signals for the same incident and suppress misleading normal-stop notifications after a crash. Generic mod errors, chat, client-only reports and subordinate service failures are excluded.
- Added optional mclo.gs report sharing, with a bounded recent-log fallback when no report is available. Webhook URLs, common credentials, IP addresses and home-directory usernames are scrubbed before upload on a best-effort basis. Automatic uploads are disabled by default.
- Configure independent destinations for crash alerts and report links: the main channel, an administrator channel, or both. Delivery/upload failures do not stop normal monitoring.
- Added optional `SERVER_PID` monitoring for Java process termination without a crash log or report. After recreating the process, update its PID and restart the notifier.
- Added pre-tag release checks requiring successful Windows/Linux builds and standalone startup checks for the exact candidate commit.

Windows x64 and Linux x64 binaries, ZIP archives and SHA-256 checksums are provided. Preserve your configuration before updating, run `--check-config`, and restart the notifier before starting the Minecraft server. Logs and reports that already exist when monitoring begins are not replayed.

Existing TOML configurations remain valid; omitted new settings use their defaults. Set `CRASH_REPORT_UPLOAD_ENABLED = true` to opt into uploads. See README and `send-minecraft-notifications.example.toml` for routing and other settings. Automatic scrubbing cannot identify every private value in arbitrary mod output.
